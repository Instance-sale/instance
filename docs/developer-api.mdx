Instance includes a REST API and a Model Context Protocol (MCP) server so external tools, scripts, and AI agents can work with your workspace. Both authenticate with a workspace API key.

---

## 1. Create an API key

API keys belong to a workspace. Owners and admins can create and revoke keys. Maintainers can view the list of keys.

1. In the dashboard, open **Settings** and select the **API Keys** tab.
2. Click **Create New Key**.
3. Enter a **Key Name / Integration Label** that describes what uses the key, then click **Generate Key**.
4. Copy the key. It starts with `inst_live_` and Instance shows it only once. After you dismiss the alert, the list shows a masked version with the last four characters.

The **Active API Keys** list shows when each key was created and last used. Click **Revoke key** to disable a key immediately.

<Warning>
Treat API keys like passwords. Anyone with a key can read and change contacts and trigger automations in your workspace.
</Warning>

---

## 2. Authenticate requests

The API is served by the API service under the `/api/v1` path. On a local install that is `http://localhost:4000/api/v1`. In production, use your API domain, for example `https://api.yourdomain.com/api/v1`.

Send the key in the `X-API-Key` header, or as a bearer token in the `Authorization` header:

```bash
curl "http://localhost:4000/api/v1/contacts?limit=25" \
  -H "X-API-Key: inst_live_your_secret_key_here"
```

```bash
curl "http://localhost:4000/api/v1/contacts?limit=25" \
  -H "Authorization: Bearer inst_live_your_secret_key_here"
```

Requests without a key, with a key that does not start with `inst_live_`, or with a revoked key return `401`.

Contact endpoints work on the first Instagram account connected to the workspace. If no account is connected yet, they return `400`.

## 3. Endpoints

All paths are relative to `/api/v1`.

### Workspace

| Method | Path | Description |
| :--- | :--- | :--- |
| `GET` | `/workspace/info` | Workspace details and connected Instagram accounts. |
| `GET` | `/tags` | List company tags. |
| `POST` | `/tags` | Create a company tag. Body: `{ "name": "VIP" }`. |
| `DELETE` | `/tags/{name}` | Delete a company tag. |
| `GET` | `/automations` | List automations. |
| `GET` | `/pipelines` | List pipeline stages. |

### Contacts

| Method | Path | Description |
| :--- | :--- | :--- |
| `GET` | `/contacts` | List contacts. Query: `page`, `limit` (default 25, max 100), `search`, `status`, `qualified` (`true` or `false`), `minScore`, `maxScore`. |
| `GET` | `/contacts/find` | Find one contact by `username`, `email`, or `phone`. |
| `GET` | `/contacts/{id}` | Get a contact. |
| `POST` | `/contacts` | Create a contact. Body: `username`, `name`, `email`, `phone`, `status`, `tags`. |
| `PATCH` | `/contacts/{id}` | Update `name`, `email`, `phone`, `status`, or `tags`. |
| `POST` | `/contacts/{id}/tags` | Add tags. Body: `{ "tags": ["VIP"] }`. |
| `DELETE` | `/contacts/{id}/tags/{name}` | Remove a tag. |
| `POST` | `/contacts/{id}/status` | Move the contact to a pipeline stage. Body: `{ "status": "Qualified" }`. |

### Audience lists

| Method | Path | Description |
| :--- | :--- | :--- |
| `GET` | `/audience-lists` | List audience lists. |
| `POST` | `/audience-lists` | Create a list. Body: `name`, `description`, `color`. |
| `GET` | `/audience-lists/{id}/contacts` | List contacts in a list. Query: `page`, `limit`, `search`, `channelFilter` (`all`, `email`, `phone`, `both`), `minScore`, `maxScore`. |
| `POST` | `/audience-lists/{id}/assign` | Add contacts to a list. Body: `{ "contactIds": ["..."] }`. |
| `DELETE` | `/audience-lists/{id}` | Delete a list. Contacts are not deleted. |

### Automations

| Method | Path | Description |
| :--- | :--- | :--- |
| `POST` | `/automations/{id}/trigger` | Run an automation for a contact. Body: `contactId` or `username`, plus optional `variables`. |

```bash
curl -X POST "http://localhost:4000/api/v1/automations/AUTOMATION_ID/trigger" \
  -H "X-API-Key: inst_live_your_secret_key_here" \
  -H "Content-Type: application/json" \
  -d '{ "username": "@customer", "variables": { "promo_code": "VIP10" } }'
```

Automations triggered through the API still follow the messaging rules on the [Safety](/safety) page.

## 4. Connect AI agents with MCP

The `instance-mcp` package is an MCP server that runs locally over standard I/O and calls the REST API with your key. It lets AI clients such as Claude Desktop, Cursor, and Claude Code look up and create contacts, update pipeline stages and tags, manage audience lists, and trigger automations.

It reads two environment variables:

| Variable | Required | Default | Description |
| :--- | :--- | :--- | :--- |
| `INSTANCE_API_KEY` | Yes | None | Your API key, starting with `inst_live_`. |
| `INSTANCE_API_URL` | No | `https://api.instance.sale` | Base URL of your API service, without `/api`. Set it to `http://localhost:4000` or your API domain when you self-host. |

Add the server to your MCP client configuration. For example, in Claude Desktop's `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "instance": {
      "command": "npx",
      "args": ["-y", "instance-mcp"],
      "env": {
        "INSTANCE_API_KEY": "inst_live_your_secret_key_here",
        "INSTANCE_API_URL": "http://localhost:4000"
      }
    }
  }
}
```

With Claude Code, add it from your terminal and set the same environment variables in your shell:

```bash
claude mcp add instance -- npx -y instance-mcp
```
